## 2. ข้อมูลในชีต — เพิ่ม 4 คอลัมน์ในแท็บ `Abilities`

| คอลัมน์ | ความหมาย | ตัวอย่าง |
|---|---|---|
| `grow` | 📈 % ที่เพิ่มทุกครั้งที่ไม่แสดงผล (บวกตรง ๆ, รีเซ็ตเมื่อออก, เพดาน 100) | `5` |
| `decay` | 📉 % ที่ลดลง (ลบตรง ๆ, ครั้งเดียว) | `50` |
| `decay_after` | 📉 ลดหลังเทิร์นที่เท่าไร (ใช้แสดงผลเท่านั้น) | `2` |
| `limit` | 🔒 แสดงผลได้สูงสุดกี่ครั้งต่อเกม (แสดงผลเท่านั้น) | `2` |

ว่าง = ไม่มี · **ไม่ต้องแก้ Sheet 1** — `Value` ยังเป็นค่าเริ่มเหมือนเดิม

| name | … | grow | decay | decay_after | limit |
|---|---|---|---|---|---|
| ขังคุก | | 5 | | | |
| แปลน 3 หลัง | | | 50 | 2 | |
| ป้องกันบังคับย้ายและดักจับ | | | | | 2 |
| กันวิคตอรี่ | | | | | 1 |

> ⚠️ เพราะเป็นของสกิล: ใส่ `grow = 5` ที่ขังคุก = **ทุก 106 จี้**ที่มีขังคุกจะเติบโต · `limit = 1` ที่กันวิคตอรี่ = ทั้ง 84 จี้ · `decay` ที่แปลน 3 หลัง = ทั้ง 119 จี้

ตรวจข้อมูล (เตือนใน console):
- ตัวเลขผิด / ติดลบ · `decay` ไม่มี `decay_after` (หรือกลับกัน)
- `grow` หรือ `decay` กับสกิล `unit = amount` (ออกแบบไว้สำหรับโอกาสเท่านั้น)
- มีทั้ง `grow` และ `decay` ในสกิลเดียว (ยังไม่กำหนดว่าคิดยังไง → ใช้แค่ `decay`)

## 3. คำนวณ (`js/search-core.js`)

เพิ่ม `effectiveValue(value, ability)` แล้วให้ `jewelToCandidate` ใช้ค่านี้แทน `value` ก่อนส่งเข้า `abilityScore` (รวมถึงกรณีเลือกทั้งกลุ่ม ที่ใช้ "ค่าสูงสุดในกลุ่ม")

### 3.1 📈 เติบโตเมื่อไม่แสดงผล
โอกาสเทิร์นที่ k หลังออกครั้งล่าสุด: `pₖ = min(100, p₀ + k·grow)`
จำนวนเทิร์นเฉลี่ยต่อการออก 1 ครั้ง: `E = Σₖ Πⱼ<ₖ (1 − pⱼ/100)` → **โอกาสเฉลี่ย = 100 / E**
(ไม่ขึ้นกับความยาวเกม · `pₖ` ถึง 100 แล้วผลรวมหยุดเอง)

| ค่าเริ่ม | grow | ใช้คิดคะแนน |
|---|---|---|
| 45% (ขังคุก) | +5 | **49.4** |
| 10% | +5 | 22.1 |
| 30% | +5 | 36.9 |
| 60% | +5 | 62.7 |
| 45% | 0 | 45.0 (เท่าเดิม) |

### 3.2 📉 ลดลงหลัง N เทิร์น
ใช้คิดคะแนน = `max(0, value − decay)` → แปลน 3 หลัง 80% −50 = **30**

### 3.3 🔒 จำกัดครั้ง
ไม่เปลี่ยนคะแนน

### 3.4 ผลต่อผลค้นหา
- คะแนนเป็นตัวตัดสิน**ลำดับสุดท้าย** (ขาดน้อย → ไม่ต้องการน้อย → แถมมาก → คะแนน) → จำนวนสกิลที่ตรงไม่เปลี่ยน · เปลี่ยนแค่ลำดับระหว่างเซ็ตที่เสมอกัน และตัวเลข "คะแนนความเทพ"
- การคัดจี้ตัวแทนต่อ mask (`PER_MASK`) ใช้คะแนนเป็นตัวตัดสินสุดท้ายเช่นกัน → จี้ที่ถูกเลือกเป็นตัวแทนอาจเปลี่ยนบ้าง
- golden ที่คาดว่าเปลี่ยน: สถานการณ์ที่มี ขังคุก / แปลน 3 หลัง (ตัวเลขคะแนน + ลำดับบางส่วน) → อธิบายใน commit

## 5. รวมชื่อที่มี "ครั้ง" กลับเป็นชื่อหลัก (G9)

| ชื่อในชีตตอนนี้ | จี้ | ชื่อหลัก | ทำได้เลย? |
|---|---|---|---|
| `ยกเลิกขังคุกทันที (2 ครั้ง)` | 8 | `ยกเลิกขังคุกทันที` + `limit = 2` | ✅ ไม่มีชื่อหลักแบบไม่จำกัดอยู่แล้ว |
| `ป้องกันเอฟเฟคอันตราย (จำกัดครั้ง)` | 5 | `ป้องกันเอฟเฟคอันตราย` | ❓ **มีชื่อหลักแบบไม่จำกัดอยู่แล้ว 142 จี้** ถ้ารวมและใส่ `limit` ที่สกิล → ทั้ง 147 จี้จะกลายเป็นจำกัดครั้ง (คำถาม Q1) |

ขั้นตอน (ต่อ 1 ชื่อ):
1. แท็บ Abilities: เปลี่ยน `name` เป็นชื่อหลัก ใส่ `limit` · ใส่ชื่อเดิมในคอลัมน์ใหม่ `old_names` (คั่นด้วย `,`)
2. Sheet 1: เปลี่ยนชื่อในช่อง Substat ของจี้ที่ใช้ชื่อเดิม
3. เว็บ: ลิงก์แชร์ / Filter ที่บันทึกที่มีชื่อเดิม → แปลงเป็นชื่อหลักอัตโนมัติผ่าน `old_names`

คอลัมน์ `old_names` ใช้ซ้ำได้กับเฟส 6 ของแผนกลุ่ม (แยกชื่อตามการแสดงผล) — แทนการเดาจากวงเล็บ

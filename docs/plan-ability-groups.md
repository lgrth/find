## 2. โครงสร้างข้อมูลในชีต

### 2.1 แท็บใหม่ `Abilities` (1 แถว = 1 สกิล)

| คอลัมน์ | บังคับ | ความหมาย | ตัวอย่าง |
|---|---|---|---|
| `name` | ✔ | ชื่อสกิล **ตรงตัวอักษร** กับที่ใช้ในช่อง Substat ของแท็บจี้ | `โล่ซูเปอร์ (ทุกการทอย)` |
| `group` | ✔ | กลุ่ม (1 สกิล 1 กลุ่ม) ว่าง = "อื่น ๆ" | `โล่` |
| `variant` | | แบบภายในกลุ่ม | `โล่ซูเปอร์` |
| `trigger` | | การแสดงผล — ข้อความอิสระ (แนะนำเลือกจาก dropdown แท็บ `Triggers`, ข้อ 2.4) | `ทุกการทอย` |
| `stack_key` | | สกิลที่ค่านี้**เหมือนกัน** ห้ามอยู่เซ็ตเดียวกัน · ว่าง = ใช้ `name` (กฎเดิม: ห้ามแค่ชื่อซ้ำ) | `โล่` |
| `unit` | | `chance` (ค่าเริ่มต้น) หรือ `amount` | `amount` |
| `max_value` | | ค่าสูงสุดสำหรับคำนวณคะแนน · ว่าง = 100 ถ้า `chance`, ค่าสูงสุดที่พบในชีตถ้า `amount` | `250` |
| `max_stack` | | จำนวนขั้นสูงสุด (แสดงอย่างเดียว) | `3` |
| `keywords` | | คำค้นหาเพิ่มเติม คั่นด้วย `,` (ย้ายมาจากแท็บ Keywords) | `บาเรีย, shield` |

- **โล่ทุกแบบใช้ `stack_key = โล่`** → ตอบ A2 (ซูเปอร์+ขาว ห้าม) และ A3 (คนละการแสดงผล ห้าม) ด้วยกฎเดียว
- สกิลอื่นที่ A2 บอกว่าใส่คู่ได้ → `stack_key` ว่าง (= ชื่อตัวเอง) ไม่ต้องทำอะไร
- สกิลที่แยกชื่อตามการแสดงผล (เช่น `ผนึกการเคลื่อนย้าย (…)` 2 แบบ) → ค่าเริ่มต้น **ใส่คู่กันได้** (Q8) · ถ้าสกิลไหนห้ามคู่ (เช่นโล่) ให้แอดมินใส่ `stack_key` เดียวกันทุกแบบ
- คอลัมน์ `pendants`, `review` ในไฟล์ร่างเป็นข้อมูลช่วยตรวจ **ไม่ต้องใส่ในชีต** (เว็บจะไม่อ่าน)

### 2.2 แท็บจี้ (เดิม) — สิ่งที่ต้องแก้
- เฉพาะสกิลที่มีหลายการแสดงผล (ตอนนี้: โล่ซูเปอร์ 143 ช่อง, โล่ขาว 42 ช่อง) ต้อง**เปลี่ยนชื่อในช่อง Substat** ให้ระบุการแสดงผล เช่น `โล่ซูเปอร์` → `โล่ซูเปอร์ (ทุกการทอย)` ตามจี้จริงแต่ละชิ้น
- ระหว่างที่ยังแก้ไม่ครบ ชื่อเดิม `โล่ซูเปอร์` ยังใช้ได้ (ใส่แถวใน Abilities: group=โล่, variant=โล่ซูเปอร์, trigger ว่าง)
- ⚠️ **ลิงก์แชร์ / Filter ที่บันทึก** ที่มีชื่อ `โล่ซูเปอร์` เดิม: หลังเปลี่ยนชื่อ ชื่อเก่าจะไม่พบ → แผนรองรับในข้อ 4.6

### 2.3 ตัวอย่างการแยกชื่อตามการแสดงผล (เฟส 6)

| แท็บจี้ — Substat (เดิม → ใหม่) | Abilities: group | variant | trigger |
|---|---|---|---|
| `โล่ซูเปอร์` → `โล่ซูเปอร์ (ทุกการทอย)` | โล่ | โล่ซูเปอร์ | ทุกการทอย |
| `โล่ขาว` → `โล่ขาว (ตกแลนด์มาร์ค/สกายแลนด์ หรือก่อสร้าง)` | โล่ | โล่ขาว | ตกแลนด์มาร์ค/สกายแลนด์ หรือก่อสร้างแลนด์มาร์ค/สกายแลนด์ |
| `ผนึกการเคลื่อนย้าย` → `ผนึกการเคลื่อนย้าย (ทอยผ่าน)` | ผนึก | ผนึกการเคลื่อนย้าย | ทอยผ่านฝ่ายตรงข้ามแล้วผนึก |
| `ผนึกการเคลื่อนย้าย` → `ผนึกการเคลื่อนย้าย (ตกพื้นที่)` | ผนึก | ผนึกการเคลื่อนย้าย | ตกพื้นที่แล้วผนึกฝ่ายตรงข้ามในแถว |

ชื่อในวงเล็บเป็นชื่อสั้นที่แอดมินตั้งเองได้ เว็บอ่าน trigger จากคอลัมน์ ไม่ได้อ่านจากวงเล็บ

### 2.4 ให้แอดมินปรับเองได้ — ไม่ต้องแก้โค้ด

ทุกอย่างเรื่องกลุ่มเป็น**ข้อมูลในชีต** เว็บสร้างแท็บกลุ่ม / ชิปแบบ / ชิปการแสดงผล จากค่าที่มีจริงในแท็บ Abilities ทุกครั้งที่โหลด

| อยากทำ | ทำในชีต |
|---|---|
| เพิ่มกลุ่มใหม่ / ย้ายสกิลไปกลุ่มอื่น | พิมพ์ชื่อกลุ่มใหม่ในคอลัมน์ `group` |
| เพิ่มการแสดงผลใหม่ | เพิ่ม 1 แถวในแท็บ `Triggers` แล้วเลือกใช้ในคอลัมน์ `trigger` |
| สกิลเดิมมีการแสดงผลเพิ่ม | เพิ่มแถว Abilities ชื่อใหม่ (variant เดิม, trigger ใหม่) แล้วใช้ชื่อนั้นในแท็บจี้ |
| กำหนดว่าใส่คู่กันได้/ไม่ได้ | คอลัมน์ `stack_key` (ค่าเหมือนกัน = ห้ามคู่) |
| เปลี่ยนขั้นสูงสุด / ค่าสูงสุด / คำค้น | คอลัมน์ `max_stack` / `max_value` / `keywords` |

**แท็บ `Triggers` (ไม่บังคับ แต่แนะนำ)** — กันพิมพ์ผิด และกำหนดลำดับชิป

| `trigger` | `order` | `note` |
|---|---|---|
| เริ่มเทิร์น | 1 | |
| ทุกการทอย | 2 | |
| ตกพื้นที่ | 3 | |
| ตกแลนด์มาร์คหรือสร้าง | 4 | |
| ตกสกายแลนด์หรือสร้าง | 5 | |
| ตกแลนด์มาร์ค/สกายแลนด์ หรือก่อสร้างแลนด์มาร์ค/สกายแลนด์ | 6 | |
| ทอยผ่านฝ่ายตรงข้ามแล้วผนึก | 7 | ผนึกการเคลื่อนย้าย |
| ตกพื้นที่แล้วผนึกฝ่ายตรงข้ามในแถว | 8 | ผนึกการเคลื่อนย้าย |

- ตั้ง dropdown ในชีต: เลือกคอลัมน์ `trigger` ของ Abilities → *ข้อมูล → การตรวจสอบข้อมูล → Dropdown (จากช่วง)* = `Triggers!A2:A` → เพิ่มแถวใน Triggers แล้ว dropdown อัปเดตเอง
- ทำแบบเดียวกันกับคอลัมน์ `group` ได้ (แท็บ `Groups`: `group`, `order`) ถ้าอยากล็อกชื่อกลุ่มและลำดับแท็บ — ไม่มีแท็บนี้ = เรียงตามจำนวนสกิล
- เว็บแจ้งเตือนใน console เมื่อ trigger/group ไม่อยู่ในแท็บอ้างอิง (สะกดผิด) แต่ยังใช้งานได้

### 2.5 แท็บ Keywords
- เลิกใช้หลังย้ายเข้า Abilities แล้ว · ช่วงเปลี่ยนผ่าน เว็บอ่านทั้งสองที่แล้วรวมกัน

## 3. โมเดลข้อมูลในโค้ด

```js
// js/data-model.js — เพิ่ม parseAbilitiesTable(table) → { abilities: Map<name, Ability>, problems }
Ability = {
  name, group /* 'อื่น ๆ' ถ้าว่าง */, variant, trigger,
  stackKey /* = name ถ้าว่าง */, unit /* 'chance'|'amount' */,
  maxValue /* number */, maxStack /* number|null */, keywords /* string[] */
}

// เงื่อนไขที่ผู้ใช้เลือก (ทั้ง "ต้องการ" และ "ไม่ต้องการ")
Requirement =
  | string                                            // สกิลเดียว (รูปแบบเดิม — ลิงก์/Filter เก่ายังใช้ได้)
  | { group: 'โล่', variants?: string[], triggers?: string[] }   // ทั้งกลุ่ม / กลุ่มที่กรองย่อย
// ว่าง/ไม่มี variants = ทุกแบบ, ไม่มี triggers = ทุกการแสดงผล

resolveRequirement(req, abilities) → Set<abilityName>   // ขยายเป็นชื่อสกิลจริง
```

- `jewel.substats[i]` ได้ข้อมูลเพิ่มจาก Abilities ตอนโหลด: `{ name, value, ability }`
- `parseTriggersTable` / `parseGroupsTable` (ไม่บังคับ) → ลำดับและรายการอ้างอิง
- ตรวจข้อมูล (แสดงใน console เหมือน `[sheet]` ตอนนี้):
  - สกิลในแท็บจี้ที่ไม่มีใน Abilities → ใช้กลุ่ม "อื่น ๆ"
  - แถว Abilities ที่ไม่มีจี้ใช้ · `trigger`/`group` ที่ไม่อยู่ในแท็บอ้างอิง · `unit` ผิด · `max_value` ไม่ใช่ตัวเลข
  - สกิลที่ค่าเป็น 0 หรือเว้นว่าง
  - สกิล `chance` ที่มีค่า > 100

## 4. การเปลี่ยนแปลงการค้นหา (`js/search-core.js`)

### 4.1 bit ของเงื่อนไข
เดิม: 1 bit = 1 ชื่อสกิล → ใหม่: **1 bit = 1 Requirement** = ชุดชื่อสกิล (OR)
```js
jewelToCandidate(j, requirements /* Set<name>[] */, unwanted /* Set<name> */)
// bit i = จี้มีสกิลใดก็ได้ใน requirements[i]
```
- worker / `searchCombos` **ไม่ต้องแก้ส่วนวนลูป** (ยังเป็น bitmask เหมือนเดิม)
- D5: ก่อนค้นหา รวมเงื่อนไขที่ซ้อนกัน (เลือก "โล่ทุกแบบ" + "โล่ซูเปอร์ (ทุกการทอย)" → เหลือเงื่อนไขกว้างอันเดียว) เพื่อไม่ให้สกิลเดียวได้ 2 bit

### 4.2 กฎห้ามซ้ำ (A1–A3)
- เดิม: เทียบ `allNames` (ชื่อสกิล) · ใหม่: เทียบ **`stackKeys`** ของจี้
- `stack_key` ว่าง = ชื่อสกิล → พฤติกรรมเดิมทุกสกิลที่ไม่ได้ตั้งค่า
- ⚠️ **เปลี่ยนผลค้นหาจริง**: ตอนนี้เว็บยอมให้ โล่ซูเปอร์ + โล่ขาว อยู่เซ็ตเดียวกัน (ผิดกฎเกม) → หลังเปลี่ยน เซ็ตแบบนั้นจะหายไป (golden test `shields` จะเปลี่ยน — ถูกต้อง)
- ใช้กับจี้ลิงก์ที่ล็อกด้วย (`compatibleWith` เทียบ stackKey)

### 4.3 คะแนน (E3, E4)
```
คะแนนสกิล   = min(value / maxValue, 1)          // chance: maxValue = 100
คะแนนจี้     = Σ (ต่อ requirement ที่จี้ตอบได้) ของ "ค่าสูงสุดในบรรดาสกิลของจี้ที่อยู่ใน requirement นั้น"   // E4
คะแนนเซ็ต   = Σ คะแนนจี้   → แสดงเป็น % หรือคูณ 100 ให้ใกล้ตัวเลขเดิม
```
- สกิล `chance` ล้วน: ลำดับ**เท่าเดิม** (หารด้วย 100 ทุกตัว) · เปลี่ยนเฉพาะเซ็ตที่มี `เพิ่มค่าผ่านทาง` / `ตกเมืองได้เงิน` (ค่า 100–250 เคยถ่วงคะแนนเกินจริง)
- ลำดับการจัดอันดับ (E2) **ไม่เปลี่ยน** — คะแนนยังเป็นตัวตัดสินสุดท้าย

### 4.4 ไม่ต้องการ (D7)
- Requirement แบบกลุ่มใช้ใน "ไม่ต้องการ" ได้ → ขยายเป็นชุดชื่อแล้วนับเหมือนเดิม

### 4.5 จำนวนเงื่อนไข (D4)
- เงื่อนไขกลุ่ม = 1 ช่องในโควตา `MAX_SELECTS = 14` · bitmask 32 bit รองรับได้

### 4.6 ชื่อสกิลเปลี่ยนจากการแยกการแสดงผล
- ถ้าลิงก์/Filter เก่ามีชื่อที่ไม่พบแล้ว แต่ชื่อนั้นเป็น "ต้นทาง" ของสกิลใหม่ (เช่น `โล่ซูเปอร์` → `โล่ซูเปอร์ (…)`) ให้แปลงเป็น Requirement `{ group:'โล่', variants:['โล่ซูเปอร์'] }` อัตโนมัติ
- วิธีหา: ชื่อใหม่ที่ขึ้นต้นด้วยชื่อเก่า + ` (` · หรือคอลัมน์ `variant` ตรงกับชื่อเก่า

## 6. UI

> **เฟส 4 ที่ทำจริง:** Requirement แบบกลุ่ม = ข้อความ `กลุ่ม:<group>` (`GROUP_PREFIX` ใน `js/search-core.js`) จึงใช้ร่วมกับ `selected`/`unwanted` แบบ string เดิมได้ทุกที่ (Filter ที่บันทึก, ลิงก์, โควตา 14) ·
> แท็บกลุ่มอยู่ใต้ช่องค้นหา (ซ่อนตอนพิมพ์ค้นหา) · ชิป `🗂 <กลุ่ม> ทุกแบบ (n)` มีเฉพาะกลุ่มที่มี ≥ 2 สกิลและไม่ใช่ "อื่น ๆ" ·
> D5 รวมอัตโนมัติด้วย `mergeRequirements` / `requirementsOverlap` (`js/filter-state.js`) · ลิงก์/Filter ที่อ้างกลุ่มที่ไม่มีแล้วจะถูกข้าม

### 6.1 เลือกสกิล (D1–D3)
```
[ ค้นหาสกิล… ]                                  ← เหมือนเดิม
[ทั้งหมด] [โล่] [ยกเว้นค่าผ่านทาง] [เพิ่มค่าผ่านทาง] [กันวิคตอรี่] …   ← แท็บกลุ่ม (เลื่อนแนวนอนบนมือถือ)

กลุ่ม: โล่                               [ + เลือกทั้งกลุ่ม ]
  แบบ:        [โล่ซูเปอร์] [โล่ขาว]                 ← ชิปกรอง (D3) ไม่เลือก = ทุกแบบ
  การแสดงผล:  [ทุกการทอย] [ตกแลนด์มาร์ค] …          ← แสดงเฉพาะ trigger ที่มีจริงในกลุ่มนั้น
  สกิล:       โล่ซูเปอร์ (ทุกการทอย) · สูงสุด 3 ขั้น   [+]
              โล่ขาว (ตกแลนด์มาร์ค) · สูงสุด 5 ขั้น    [+]
```
- กด **เลือกทั้งกลุ่ม** → เพิ่มชิป `🗂 โล่ · ซูเปอร์ · ทุกการแสดงผล` ในรายการที่เลือก (กดชิปเพื่อแก้ตัวกรองย่อย)
- กลุ่มที่มีสกิลเดียว ไม่แสดงปุ่มเลือกทั้งกลุ่ม
- ช่องค้นหาค้นได้ทั้งชื่อสกิล คำค้น และชื่อกลุ่ม
- D5: ถ้าเลือกซ้อน แสดง toast "รวมเป็น 'โล่ ทุกแบบ' แล้ว"
- "ไม่ต้องการ" ใช้คอมโพเนนต์เดียวกัน (D7)

### 6.2 การ์ดผลลัพธ์ (E1)

### จี้ชื่อซ้ำในแท็บจี้ (7 ชื่อ)
ชื่อจี้ใช้เป็นตัวระบุ (ID) ในคลังจี้ ลิงก์แชร์ และการ์ดผลลัพธ์ — ถ้า 2 แถวชื่อเดียวกัน เว็บแยกไม่ออก:
คลังจี้ติ๊ก "มีแล้ว" ทั้งสองแถวพร้อมกัน, การ์ดผลลัพธ์แสดงค่าของแถวหลังเสมอ, และผลค้นหาอาจมี 2 เซ็ตที่หน้าตาเหมือนกันแต่คะแนนต่างกัน

| จี้ | แถว | ความต่าง |
|---|---|---|
| [ดาร์ค] กับดักสปริงโล่ซูเปอร์ | 88 / 89 | กับดักสปริง 65 / 60 |
| [ดาร์ค] จรวดอวกาศของราชาที่ถูกเนรเทศ | 126 / 127 | เนรเทศ 85/80, สร้างแลนด์มาร์คแล้วเคลื่อนย้าย 55/50 |
